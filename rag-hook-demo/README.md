# 왜 RAG인가? 수업 도입용 데모

LLM에게 같은 질문을 두 번 던지는 아주 작은 웹 앱입니다. 한 번은 모델 혼자 답하게 하고, 한 번은 카페 정보를 프롬프트에 붙여 넣고 답하게 합니다. 청킹, 임베딩, 벡터 DB를 배우기 전에 RAG의 핵심 아이디어를 먼저 보여 줍니다.

동작 원리와 코드 설명은 [HOW_IT_WORKS.md](HOW_IT_WORKS.md)에 있습니다. 학생들에게 도구를 설명할 때 이 문서를 같이 보여 주세요.

## 실행 방법

```bash
pip install -r requirements.txt
cp .env.example .env      # 그다음 .env 파일에 API 키를 넣으세요
python app.py
```

브라우저에서 http://127.0.0.1:5000 을 여세요.

OpenAI 호환 API라면 어떤 것이든 동작합니다. `.env.example`에 xAI Grok과 Groq 설정이 들어 있습니다.

## 수업에서 데모 진행 순서

1. **모델 혼자.** "금요일에 텀블러 할인되나요?"를 *모델에게만 질문*으로 물어봅니다. 모델은 빈 브릿지 카페의 규칙을 본 적이 없으므로 추측하거나 모른다고 답합니다. 학생들에게 물어보세요. 이 답이 맞나요? 어떻게 확인할 수 있을까요?
2. **모델 + 카페 정보.** 같은 질문을 *카페 정보와 함께 질문*으로 물어봅니다. 이제 정확하게 답합니다(할인은 화요일에만). *전송된 프롬프트 보기*를 열어서 모델은 전혀 바뀌지 않았다는 점을 짚어 주세요. 우리는 올바른 텍스트를 프롬프트에 붙여 넣었을 뿐입니다. 이것이 RAG이고, 남은 수업은 이 단계를 자동화하는 방법을 다룹니다.
3. **파일에 없는 내용.** "무료 와이파이 있나요?"를 물어봅니다. 근거 기반 답변이라면 정보에 해당 내용이 없다고 말해야 합니다.
4. **실시간 수정.** 영수증의 규칙을 바꾸고(예: 텀블러 할인을 금요일 1,000원으로) 다시 질문합니다. 답은 모델의 기억이 아니라 텍스트를 따라갑니다.
5. **시스템의 파일을 바꾸기.** 브라우저가 아니라 에디터(VS Code 등)에서 `cafe_info.txt`를 직접 고치고 저장합니다. 2초 안에 화면의 영수증이 자동으로 갱신됩니다. 다시 질문하면 답이 바뀐 파일을 따라갑니다. 반대로 화면에서 고친 내용은 *파일에 저장*을 누르면 디스크에 기록되고, 에디터에서 바뀐 파일을 볼 수 있습니다. 핵심 메시지: 모델이 아는 것은 우리가 시스템에 넣어 둔 데이터가 전부이고, 데이터를 바꾸면 답도 바뀝니다.
6. **연결 질문.** "이 파일은 다섯 줄입니다. 카페 체인에 300쪽짜리 매뉴얼이 있다면 어떻게 할까요?" 여기서 청킹과 검색으로 넘어갑니다. 실제로 보여 주려면 긴 버전으로 바꿔 봅니다.

   ```bash
   cp cafe_info.txt cafe_info_short.txt     # 짧은 버전 보관
   cp cafe_info_long.txt cafe_info.txt      # 150줄짜리 운영 매뉴얼로 교체
   ```

   또는 `app.py`의 `INFO_FILE` 한 줄을 `cafe_info_long.txt`로 바꾸고 서버를 다시 실행해도 됩니다. 화면의 영수증이 자동으로 길어집니다. *전송된 프롬프트 보기*를 열어 질문 하나에 매뉴얼 전체가 통째로 들어가는 것을 보여 주세요. "2층 대관 비용은?" 같은 질문은 잘 답하지만, 프롬프트가 매번 이만큼 길어지는 것이 비용과 한계의 출발점입니다. 그래서 필요한 부분만 찾아 넣는 검색(retrieval)이 필요합니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `app.py` | Flask 서버. 학생이 꼭 읽어야 할 함수는 `build_messages()` 하나입니다. 일반 프롬프트와 증강된 프롬프트의 차이를 보여 줍니다. |
| `/info` (app.py) | 디스크의 `cafe_info.txt`를 읽고(GET) 쓰는(POST) 작은 API. 화면이 2초마다 파일 수정 시각을 확인해 바뀌면 자동으로 다시 불러옵니다. |
| `templates/index.html` | 데모 화면. |
| `HOW_IT_WORKS.md` | 학생용 설명 문서. 구조, 요청 흐름, 핵심 함수, 실습 과제, 자주 나오는 질문. |
| `cafe_info.txt` | 카페의 비공개 정보(지어낸 내용이라 어떤 모델도 알 수 없습니다). 디스크의 이 파일이 기준 데이터입니다. |
| `cafe_info_long.txt` | 같은 카페의 150줄짜리 운영 매뉴얼. 영업시간, 메뉴, 알레르기, 할인, 멤버십, 대관 등 12개 섹션. 원래 다섯 가지 규칙은 그대로 들어 있고 와이파이는 일부러 뺐습니다. |
