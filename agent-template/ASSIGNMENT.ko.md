# 팀 실습 — 나만의 에이전트 만들기

English: [ASSIGNMENT.md](ASSIGNMENT.md)

카페 에이전트를 완성했습니다. 이번에는 팀이 새로운 에이전트를 직접 기획합니다.

**형식은 그대로, 아이디어는 새롭게.**

에이전트 루프, LLM 클라이언트, 설정 파일은 커피에 대해 아무것도 모릅니다. 그래서 고치지 않고 그대로 복사해서 씁니다. 카페 에이전트를 *카페* 에이전트로 만든 것은 브리프, 도구 명세, 도구, 데이터, 시스템 프롬프트였습니다. 여러분이 새로 쓰는 부분이 바로 이것입니다.

## 무엇을 만드나요

팀이 직접 고른 사용자와 문제를 위한 어시스턴트입니다. 예를 들면 기숙사 세탁실, 동아리 총무, 동물병원 접수 데스크, 공부 계획표가 있습니다. 이것은 출발점일 뿐입니다. 다른 팀에 없는 아이디어일수록 좋습니다.

## 요구 사항

에이전트는 다음을 모두 갖춰야 합니다.

- [ ] **새 도구 4개 이상.** `calculate`는 이미 있으므로 개수에 넣지 않습니다.
- [ ] **세 가지 유형 모두.** `read`, `write`, `compute` 도구가 각각 하나 이상 있어야 합니다. (`calculate`를 compute 도구로 써도 됩니다.)
- [ ] **카페에는 없는 도구 하나.** 아래 "이름만 바꾸기 테스트"를 보세요.
- [ ] **모든 도구의 명세.** 코드보다 *먼저* `docs/03_tool_spec.md`에 씁니다.
- [ ] **로컬 JSON 데이터만 사용.** `data/` 폴더에 둡니다. 가짜 데이터도 괜찮습니다 (가짜 날씨, 가짜 가격).
- [ ] **먼저 물어보는 write 도구.** 에이전트가 데이터를 바꾸기 전에 사용자에게 확인합니다.
- [ ] **시나리오 3개.** `tests/scenarios.md`에 씁니다.
  - 도구 3개를 연달아 써야 하는 시나리오
  - 도구가 오류를 돌려주고 에이전트가 회복하는 시나리오
  - write 전에 확인하는 모습을 보여 주는 시나리오
- [ ] **형식 검사기 통과.** `python -m pytest tests/test_tool_format.py`

## 이름만 바꾸기 테스트

도구 목록에서 여러분의 명사를 카페 단어로 바꿔 보세요. 카페 에이전트가 그대로 나오면 이름만 바꾼 복제품입니다.

| 도구 목록 | 판정 |
|---|---|
| `get_books`, `check_copies`, `record_loan`, `get_loan_report` | 이름만 바꾼 것. 커피를 책으로 바꾼 카페 에이전트입니다. |
| `get_books`, `check_copies`, `record_loan`, `find_next_return_date`, `suggest_similar_book` | 좋음. 마지막 두 도구는 도서관에서만 의미가 있습니다. |

이렇게 물어보세요. *카페 사장님에게는 필요 없지만 우리 사용자에게는 꼭 필요한 것이 무엇인가?* 그 답이 가장 흥미로운 도구가 됩니다.

## 팀 역할

2명이 한 팀입니다. 각자 도구를 두 개씩 맡습니다. 맡은 도구의 명세를 직접 쓰고, 그 코드를 설명할 수 있어야 합니다.

| 역할 | 하는 일 |
|---|---|
| 리더 (Lead) | `docs/01_brief.md`를 씁니다. 범위에 넣을 것과 뺄 것을 정합니다. |
| 설계자 (Designer) | `docs/03_tool_spec.md`가 일관되게 유지되도록 합니다. 도구들이 서로 이어지는지 확인합니다. |
| 드라이버 (Driver) | AI 코딩 어시스턴트에게 프롬프트를 입력합니다. 한 번에 도구 하나씩 합니다. |
| 테스터 (Tester) | 테스트와 시나리오를 씁니다. 도구를 하나 만들 때마다 형식 검사기를 실행합니다. |

2명이므로 한 사람은 리더 겸 설계자, 다른 한 사람은 드라이버 겸 테스터를 맡습니다.

## 발표 (3분)

1. 사용자와 문제를 한 문장으로 말합니다.
2. 도구 3개짜리 시나리오를 그 자리에서 실행합니다. 도구 호출 과정을 보여 줍니다.
3. 오류 시나리오를 그 자리에서 실행합니다.
4. 교수자가 팀원 한 명과 도구 하나를 고릅니다. 그 팀원이 코드를 설명합니다.

## 자주 하는 실수

- **명세보다 코드를 먼저 쓴다.** 명세의 Purpose 줄이 곧 LLM이 읽는 도구 설명입니다. 그것부터 씁니다.
- **거대한 도구 하나를 만든다.** `manage_library(action, ...)` 같은 도구는 LLM이 쓰기 어렵습니다. 한 가지 일만 하는 작은 도구를 여러 개 만듭니다.
- **전부 다 돌려준다.** 기록 200개를 돌려주는 도구는 컨텍스트를 낭비합니다. 요약을 돌려줍니다.
- **힌트 없는 오류를 돌려준다.** `{"error": "not found"}`를 받으면 에이전트는 멈춥니다. `{"error": "Book 'Dune 2' not found. Call search_books to see valid titles."}`를 받으면 스스로 회복합니다.
- **AI 어시스턴트에게 한꺼번에 다 시킨다.** 프롬프트 하나에 도구 하나입니다. 확인한 뒤 다음 도구로 넘어갑니다.
